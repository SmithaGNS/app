# Non-functional contract

The prototype is an in-memory page with no network, no submitting `<form>` and no time zone handling, so it holds no opinion on any of this. Every row below is **PROPOSED**; none is ratified. Answering once here is cheaper than 15 screens answering differently.

| Area | What the set found | Contract (PROPOSED) |
|---|---|---|
| Loading | No loading state on any screen; login double-submit risk (OQ-A-02, OQ-V-02, OQ-10-02, OQ-20-07, OQ-21-07) | A control that starts a request is disabled and shows a spinner at once; a list shows 5 skeleton rows after 300 ms of waiting; no indicator below 300 ms. Submit buttons stay disabled until the response arrives. |
| Server errors | No failure UI; the prototype cannot fail (OQ-20-07, OQ-21-07) | A failed read shows an inline error panel with a Retry button; a failed write keeps the dialog open, keeps entered values and shows the error above the buttons. Reads and idempotent writes are retryable; OTP verify and Send reply are not retried automatically. Server validation rejections map to the field's own message. |
| Enter key | Login and Forgot do not submit on Enter (OQ-A-08); Config and Profile do; dialogs are not forms | Enter submits every single-purpose form (login, forgot, OTP, config, profile, dialogs with one primary action). Enter inside a multi-line box inserts a newline. |
| Focus on arrival | Dialogs focus the close button; nothing else specified | Page: focus the page heading (first field on auth screens). Dialog: focus the first invalid or first editable field, not the close button. |
| Modal focus | No focus trap; Escape and backdrop never restore focus; focus lost to BODY after Edit Save, review Save and Logout Cancel (OQ-A-21) | Trap Tab inside the dialog. Escape and backdrop behave like Cancel. On every dismissal, including Save, return focus to the opener or, if it was re-rendered, to the equivalent control on the same row. |
| Empty state | None specified; seed lists are never empty (OQ-10-02, OQ-11-02, OQ-13-02) | Two shapes: "nothing here yet" (no records exist; message plus the Add action where permitted) and "nothing matched" (a filter or search is active; message names the criteria and offers Reset). |
| Time zones | Created At zone unknown (OQ-V-17); Replied At uses the browser clock (SCR-13); Last login UTC or local unknown (OQ-22-02) | Store every timestamp in UTC. Render in the signed-in user's browser zone. Date filters are read in that zone and converted to a UTC range. Stamps (Replied At, Status Updated) come from the server clock, never the browser. |
| Pagination | Page-size select and pagers are dead on all six lists; counts are constants (OQ-V-13, OQ-13-04, OQ-21-06, LISTSCOPE) | Server-side paging, default 10, options 10/25/50/100; footer "Showing x to y of N" with N exact and from the same query as the rows; search and filters apply to all rows, not the loaded page; a page past the last returns the last page. |
| Search | The prototype filters only loaded rows; no maximum (OQ-V-26) | Server-side across all rows, maximum 100 characters, debounced 300 ms. |
| Permission denial | No role is enforced anywhere (OQ-A-27, OQ-20-02) | A screen out of scope is absent from the sidebar; an action out of scope on a visible screen is disabled with a reason tooltip. The server refuses with 403 regardless, and a refused press shows "You do not have permission to do this." Fill the matrix from the ROLES answer before building; until then one check, no hard-coded rights. |
| Destructive actions | Delete is a native `confirm()` with no protections and no toast (OQ-10-05, OQ-20-08) | In-page dialog naming the record and the consequence, with Cancel; success shows a toast. Deletion rules per DM-02 and REFINT. |
| Personal data | Full phone numbers in aria-labels and toast; exports would leak (OQ-V-19, OQ-21-11, EXPORT-PII) | Phone numbers masked by default everywhere, including aria-labels, toasts and exports; reveal is permission-checked and audit-logged. |
| Validation | Several limits in the stories are PROPOSED | Every limit in the stories' Validation tables is enforced on the server as well as the client, with identical messages. |
| Accessibility | Live region for toasts exists; gaps above | Visible focus, labels bound to inputs, errors announced, wide tables scroll inside their container. |
| Responsive | Measured thresholds per list are in the stories | Below 1024 px the sidebar is an off-canvas drawer (SCR-04). Pinning the SCR-20 Option column is PROPOSED (OQ-20-13). |
| Seed data | The prototype fixtures carry defects: hard-coded counts, "Admin Admin", mixed phone formats, a seed email that fails its own regex | Do not seed from the prototype. Author clean seed data; the defects above must not be re-imported. |
